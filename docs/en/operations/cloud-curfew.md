# The 11 pm curfew hook for cloud sessions

English | [简体中文](../../operations/cloud-curfew.md)

> Translated from the Chinese original. If they disagree, the Chinese version wins. Terms: [glossary](../../glossary.md).

## Why

After 11 pm, new prompts you send to Claude Code are blocked (rules in [devices.md](devices.md), "Workaholic index and evening curfew").
On the Mac the hook lives in `~/.claude/settings.json` and applies to every session. Cloud sessions used to rely only on the repo's `.claude/settings.json` — but **cloud sessions are often opened from a parent directory such as `/home/user` (one session, several repos), where the repo's settings aren't read**, so the hook silently didn't apply.

Fix: add a snippet to the cloud environment's **Setup script** on claude.ai that writes the curfew hook into `~/.claude/settings.json` (user level, read no matter which directory the session starts in) every time the environment starts.

- The script contains **no keys**. The hook reads `ETHAN_CLOUD_TOKEN` from the environment only when it runs (the setup script itself can't see environment secrets and doesn't need to).
- Scheduled-task wake-ups and patrol messages containing “定时巡检” are let through, so night patrols keep working.
- If the server can't be reached the prompt is allowed — a session never gets stuck; errors in the script don't break environment startup (`|| true`).
- Running alongside the repo's copy only means one extra request to the server; the result is the same.

## What you do (once, about 2 minutes)

1. Open claude.ai/code. Under the new-session input, open the environment picker, hover the environment you use (e.g. Default) and click the gear icon.
2. Find **Setup script** and paste the whole block below **at the end** of what's there (or into the empty box). Save.
3. It takes effect in new cloud sessions. Check: in a new session run `python3 -m ethan.setup_hook --check`; the first line should say that `…/.claude/settings.json` has the curfew hook (active in cloud sessions only).

The block (you can also generate it with `python3 -m ethan.setup_hook --where cloud-user`; the content is identical):

```bash
# 小伴 收工钩子（python3 -m ethan.setup_hook --where cloud-user 生成，docs/operations/cloud-curfew.md）
# 11 点后她发的新指令挡回；定时任务唤醒和“定时巡检”放行。不含钥匙，钩子运行时读 ETHAN_CLOUD_TOKEN。
mkdir -p "$HOME/.claude"
python3 - <<'ETHAN_CURFEW_PY' || true
import json, os
p = os.path.expanduser("~/.claude/settings.json")
try:
    s = json.load(open(p, encoding="utf-8"))
except Exception:
    s = {}
cmd = "[ \"$CLAUDE_CODE_REMOTE\" = true ] || exit 0; case \"$(cat)\" in *queued-remote-notifications*|*定时巡检*) exit 0;; esac; t=\"${ETHAN_HOOK_TOKEN:-$ETHAN_CLOUD_TOKEN}\"; [ -n \"$t\" ] || exit 0; r=$(curl -s -m 4 -A ethan-curfew -H \"Authorization: Bearer $t\" \"https://ethan.example.com/cloud/curfew\") || exit 0; printf '%s' \"$r\" | python3 -c 'import json,sys\ntry:\n d=json.load(sys.stdin)\nexcept Exception:\n sys.exit(0)\nif d.get(\"stop\"):\n print(d.get(\"message\") or \"已经 11 点了，今天到这儿。\", file=sys.stderr); sys.exit(2)'"
hooks = s.setdefault("hooks", {})
groups = [g for g in hooks.get("UserPromptSubmit", []) if not any("ethan-curfew" in h.get("command", "") for h in g.get("hooks", []))]
groups.append({"hooks": [{"type": "command", "command": cmd, "timeout": 8}]})
hooks["UserPromptSubmit"] = groups
json.dump(s, open(p, "w", encoding="utf-8"), ensure_ascii=False, indent=2)
print("小伴 收工钩子已写进", p)
ETHAN_CURFEW_PY
```

The comments and messages in the block are in Chinese because it's generated by the code; generate your own with the command above rather than editing it by hand. Whenever the hook changes (`curfew_command` in `ethan/setup_hook.py`), paste the newly generated block again. `tests/test_syscheck.py` checks that the repo settings match the generated hook, that re-running leaves exactly one copy, and that it contains no keys.

## Checking server-side sessions

Sessions on the server (`claude remote-control`, worktree mode) read the `ethan` user's `~/.claude/settings.json` and the repo copy's `.claude/settings.json`. From your computer:

```bash
ssh my-server "sudo -u ethan -H bash -c 'cd ~/Personal-OS && python3 -m ethan.setup_hook --check --repo .'"
```

It lists whether each file has the curfew hook, whether the hook is cloud-only (checks `CLAUDE_CODE_REMOTE`), and that machine's value of `CLAUDE_CODE_REMOTE` (it only says whether a key is present, never prints it).
Server sessions are mostly sent by development sessions to do work, so blocking them makes no sense; finding no hook there is normal — **don't install it**.
